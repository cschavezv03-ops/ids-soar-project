The two error cells are not interchangeable and the system does not
treat them as such. A false negative costs one missed flow, and the
SOAR groups hundreds of flows per attack into one case, so a single
attack survives many misses. A false positive blocks a real user.

4. CURVES AND THRESHOLD-INDEPENDENT SCORES
==============================================================================
    model                        ROC-AUC      PR-AUC
    Random Forest                 0.9994      0.9979
    Logistic regression           0.9839      0.9391
    chance (prevalence)           0.5000      0.1667

WHY PR-AUC IS THE ONE TO READ HERE. The test set is 16.67% attacks. A
ROC curve plots recall against the FALSE POSITIVE RATE, whose
denominator is the 331,691 benign flows - so thousands of false
positives still move it barely at all, and every model looks
excellent. Precision-Recall uses precision instead, whose denominator
is what the model actually flagged, so it degrades as soon as the
model starts alarming on benign traffic. Chance level makes the point:
    ROC-AUC of a coin flip = 0.5000, PR-AUC of a coin flip = 0.1667.
A ROC-AUC of 0.99 is 'better than a coin flip'. A PR-AUC of 0.99 is
six times the prevalence floor. Only the second is informative.

HOW TO READ THE 'Rule NAIVE' COLUMN - it is not a good detector.
    At a glance it looks like the best model in the table: 1.0000 on
    both Patators, 0.9998 on DDoS. It reaches those numbers by
    flagging 391,014 of 398,033 test flows as
    attacks - including 325,624 of the 331,691 benign ones, a
    false positive rate of 0.9817.
    Its recall is high for the same reason a smoke alarm that is
    always sounding has perfect recall. This is exactly why recall is
    never read on its own here, and why the BENIGN row of this table
    is part of it rather than a separate note.

FINDING 1 - the fixed rule zeroes out four families.
    FTP-Patator 0.0000, SSH-Patator 0.0000, PortScan 0.0857, DDoS
    0.1649. None of the four separates from normal traffic BY RATE:
    brute force is identified by how regular its packet sizes are, a
    port scan by tiny flows carrying no payload, and DDoS sits on the
    wrong side of a rule that ended up meaning 'slow flow = attack'.
    This is the measured form of the project's central argument. The
    rule does not fail because it is a simple model; it fails because
    ONE feature cannot describe four different shapes of attack, and a
    threshold can only look at one.

FINDING 2 - an aggregate can hide two entire families.
    Logistic regression scores F1 0.8151 overall, which reads as a
    respectable model, while scoring 0.0008 on FTP-Patator and 0.0000
    on SSH-Patator. Both are demo scenarios. A single headline number
    would have concluded that the linear model is adequate; this table
    is the concrete reason this project does not evaluate on one.

Chosen model: RANDOM FOREST.

    attack-class F1 on test   0.9920   vs 0.8151 (logistic) and 0.6015 (fixed rule, fitted direction)

It wins on every axis measured here, and - the reason that matters -
it is the only one of the three that detects all nine families. See
contract/A5_evaluation_note.md for the written decision, the corrected
defence argument and the domain-shift risk this number does NOT cover.
