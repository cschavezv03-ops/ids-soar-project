2. THE OPERATING POINT
==============================================================================
Read from src/common/config.py, which is the single source of truth
shared with component B. This run refuses to start if they disagree.

    < 0.70          ignored, no case opened
    [0.70, 0.90)    MEDIUM severity -> short containment, 300 s
    >= 0.90         HIGH severity   -> full containment,  600 s

TWO TIERS RATHER THAN ONE. The two errors do not cost the same. A false
negative costs one missed flow, and the SOAR groups hundreds of flows
per attack into one case, so an attack survives many misses. A false
positive fires iptables at a real user, and that cost does not dilute.
A single cut forces one answer to two different questions; two tiers
let a borderline flow cost five minutes and a confident one ten.

    either clearly below 0.70 or clearly above 0.90 - so the middle is

    OPEN A CASE. One benign flow at 0.75 must not block anyone. An

4. PER-FAMILY RECALL ACROSS THE CANDIDATE CUTS
==============================================================================
A5 showed that an aggregate can hide a whole family. Choosing a
threshold on the aggregate alone would repeat exactly that mistake.

    SSH-Patator         recall                     630   0.9667   0.9587   0.9508   0.9492   0.9381   0.9254
    PortScan            recall                     385   0.9429   0.8779   0.8468   0.7896   0.7325   0.6597

THIS IS WHY THE CUT IS NOT PUSHED HIGHER. Going to 0.99 would drop
false positives to 140, but PortScan per-flow recall falls to 0.6597
and DoS Slowhttptest to 0.8010 - the two smallest families, and one of
them is a demo scenario. At 0.70 no family drops below 0.87.

The counter-argument, for completeness: per-flow recall is not
per-attack recall. A scan of 100 flows at 0.6597 recall is missed
entirely with probability 0.34^100, which is not a number that
happens. The reason to stay at 0.70 is therefore NOT that 0.99 would
miss scans - it would not. It is that a lower cut costs little, keeps
the severity bands meaningful, and leaves margin for the domain shift
A7 has to measure. A threshold tuned to the last decimal on CICIDS2017
would be false precision about a network we have not measured yet.

==============================================================================
5. THE NUMBER THIS THRESHOLD DOES NOT FIX: THE BASE RATE
==============================================================================
The test set is 16.67% attacks. A real network between attacks is
nowhere near that, and precision depends on it. Same model, same cut,
different arithmetic.

       thr   recall       FPR   prev 16.67%    prev 5.00%    prev 1.00%    prev 0.10%
      0.50   0.9953   0.00228        0.9887        0.9583        0.8150        0.3039
      0.70   0.9934   0.00189        0.9906        0.9652        0.8417        0.3451
      0.90   0.9901   0.00096        0.9952        0.9819        0.9123        0.5075
      0.99   0.9810   0.00042        0.9979        0.9919        0.9591        0.6994

At the chosen cut the model produces 189 false alarms per 100,000 benign flows,
whatever the prevalence. When attacks are 0.1% of traffic those swamp
the true positives and precision falls to 0.3451.

NO THRESHOLD FIXES THIS - it is arithmetic, not a model defect. What
fixes it is the SOAR requiring several flows from the same IP before
opening a case, and A7 measuring the false positive rate on the lab's
own benign traffic, which has never been measured.
