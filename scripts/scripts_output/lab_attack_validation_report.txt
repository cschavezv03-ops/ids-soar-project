==============================================================================
4. TWO PREDICTIONS THE MEASUREMENT REFUTES
==============================================================================
PREDICTION 1 (A7 note section 9): an answered HTTP flood would be
detected because CICIDS2017's DDoS scores 0.9990.
    MEASURED: 3.8% per-flow at the cut, not ~99%. Our flood
    is SHORTER (median duration 42 ms vs 1.9 s) and its server
    response is smaller, so it sits below where DDoS sits. BUT it
    emits 25,068 flows, 958 of
    them over the cut, so as a CASE it is caught with certainty. The
    refined claim: detected at case level, not at flow level.

PREDICTION 2 (A7 note section 7.2): slowloris is where the model does
best, and the SOAR rate rule cannot help because it opens few
connections.
    MEASURED: BOTH halves are wrong. The model scores 0.0% - our
    victim (Apache) ANSWERS the half-open request with a 400, so the
    flow carries backward bytes, while CICIDS2017's slowloris hit a
    server that stayed silent (totlen_bwd = 0). And slowloris opens
    MANY connections: 486 per IP per 10 s, which the SOAR rate rule
    catches. Detection here is the SOAR's job, not the model's.
